# battle_fast2_node.py 修改汇总

日期：2026-06-29

## 修改目标

在保留原 `battle_fast2_node.py` 可运行启发式逻辑的基础上，新增一套无地图、无全局定位的可达性风险感知控制核心。新核心优先运行；如果无解或异常，默认回退到原来的最大间隙启发式流程。

## 修改文件

- `roboracer_china_2025/reachability_core.py`
- `roboracer_china_2025/battle_fast2_node.py`
- `launch/battle_fast2.launch.py`
- `test/test_reachability_core.py`

## 核心新增功能

### 1. 新增 R2-Gap-Lite 可达性核心

新增 `reachability_core.py`，不依赖 ROS 2，只依赖 Python 标准库和 `numpy`。

核心流程：

```text
LaserScan ranges
-> 有效 beam / 未知 beam 建模
-> 枚举 Ackermann constant-curvature 候选弧线
-> 结合前向 beam 净空和车辆矩形扫掠体评估风险
-> 按制动距离、系统延迟、曲率限制计算安全速度
-> 用连续评分选择 steer + speed
```

这替代了“只选最大空隙中心角”的单一决策方式。

### 2. `battle_fast2_node.py` 接入新核心

节点启动后默认启用可达性核心：

```python
use_reachability_core = True
reachability_fallback_to_original = True
```

每次收到 `/scan` 后，节点会先尝试：

```text
raw LaserScan -> select_reachable_gap() -> AckermannDriveStamped
```

如果结果有效，直接发布 `/drive` 并返回；如果结果无效或核心抛异常，则默认继续执行原来的启发式算法。

### 3. 保留原算法作为安全回退

原 `middle_line_callback()` 的旧逻辑没有删除。新增逻辑只在回调开头插入：

```text
try_reachability_control()
成功：发布新控制并 return
失败：进入原始启发式流程
```

这样实车调试时可以快速切回旧逻辑。

### 4. 新增可调参数

节点新增参数：

- `use_reachability_core`
- `reachability_fallback_to_original`
- `reachability_max_speed`
- `reachability_min_speed`
- `reachability_wheelbase`
- `reachability_vehicle_width`
- `reachability_horizon`
- `reachability_max_steer`
- `reachability_steer_samples`
- `reachability_base_margin`
- `reachability_system_delay`
- `reachability_max_brake_accel`
- `reachability_max_lateral_accel`
- `reachability_unknown_weight`
- `reachability_range_max`

`battle_fast2.launch.py` 额外暴露了常用参数：

```bash

reachability_fallback_to_original
reachability_max_speed
reachability_vehicle_width
reachability_base_margin
reachability_system_delay
```

示例：

```bash
ros2 launch roboracer_china_2025 battle_fast2.launch.py use_reachability_core:=false
```

## 行为变化

### 原逻辑

```text
障碍分段 -> 最大空隙区间 -> max_dir_index -> PD 转角 -> 启发式 speed_rate
```

### 新逻辑

```text
候选转角弧线 -> 车辆扫掠风险 -> 延迟制动限速 -> 曲率限速 -> 连续评分
```

主要区别：

- 不再只根据角度空隙大小选择方向。
- 会考虑车辆宽度和安全裕量。
- 会根据前方可停止距离自动压速度。
- 会惩罚无效、未知或丢失的 LiDAR beam。
- 会惩罚转角突变，减少左右摇摆。

## 单元测试

新增 `test/test_reachability_core.py`，覆盖两个核心场景：

1. 开阔直道：应接近直行并输出较高速度。
2. 正前方障碍、右侧更开阔：应选择右转，并因净空变小主动降速。

# 2026-06-30 R2-Gap-Lite Corridor v1 修改汇总

## 修改目标

R2-Gap-Lite Plus 已经能做安全可达避障、风险调速、候选置信度和动态障碍风险，但在宽赛道上仍偏向“哪里最空走哪里”。本次在其前面加入局部赛道走廊估计，使控制逻辑变成：

```text
LaserScan
 -> local corridor estimation
 -> reachable arc safety filter
 -> corridor-conditioned candidate scoring
 -> Ackermann drive command
```

也就是先保证候选弧线安全，再优先选择沿局部赛道切向、靠近局部中心线的轨迹。

## 新增局部走廊估计核心

新增文件：

- `roboracer_china_2025/local_corridor_core.py`

该模块不依赖 ROS 2，只依赖 Python 标准库和 `numpy`，可直接单元测试。核心输出 `CorridorEstimate`：

```text
observability_mode: two_boundary / single_boundary / unobservable
visible_boundary: both / left / right / none
track_tangent: 局部赛道切向角
center_offset: 局部中心线相对车体坐标 y 方向偏移
estimated_width: 估计赛道宽度
confidence: 走廊估计置信度
```

三种模式：

- `two_boundary`：左右边界都可见，用左右边界距离估计赛道宽度和中心偏移。
- `single_boundary`：只有一侧边界可见，用 `corridor_track_width_prior` 补虚拟另一侧边界。
- `unobservable`：两侧边界都不可见，按上一帧走廊方向衰减保持，并降低置信度。

中心偏移定义：

```text
center_offset = (left_distance - right_distance) / 2
```

若左侧更远、右侧更近，`center_offset > 0`，表示局部中心线在车辆左侧，候选轨迹会被引导向左回中心。

## Reachability 评分新增 Corridor 条件项

`select_reachable_gap()` 新增可选参数：

```python
corridor=None
```

不传该参数时，旧 R2-Gap-Lite Plus 行为保持兼容。传入 corridor 后，候选弧线评分额外加入：

```text
corridor_score =
  corridor_progress_weight * progress_along_tangent
- corridor_center_weight   * normalized_center_error
- corridor_heading_weight  * heading_error
```

其中：

```text
target_y = center_offset + x * tan(track_tangent)
center_error = y_end - target_y
```

这样候选不再只追求最大自由距离，而是优先在安全候选中选择更贴近局部赛道中心线、且更沿赛道切向前进的轨迹。

低可观测模式还会降速：

- `single_boundary`：按 `corridor_single_boundary_speed_scale` 降速。
- `unobservable`：按 `corridor_unobservable_speed_scale` 更强降速。

## 修正实测速度输入

`battle_fast2_node.py` 新增 `/odom` 订阅：

```text
odom_topic = /odom
```

新增 `odom_callback()`，用 `msg.twist.twist.linear.x/y` 计算实测速度模长。`select_reachable_gap()` 的 `current_speed` 现在来自：

```python
current_speed=self.current_measured_speed()
```

不再直接使用：

```python
current_speed=float(self.last_reachability_speed)
```

这修正了制动距离和安全速度模型依赖上一帧命令速度的短板。

# R2-Gap-Lite Plus 第二层创新补充

日期：2026-06-29

## 修改目标

在已经稳定运行的 R2-Gap-Lite 可达性控制基础上，继续加入三项轻量创新：

- 风险自适应速度
- 候选轨迹置信度
- 基于连续两帧 `LaserScan` 的对手车/动态障碍预测

本次仍保持无地图、无全局定位、无外部感知依赖，核心逻辑继续放在 `reachability_core.py`，ROS 2 节点只负责传入上一帧雷达和时间差。

## 核心原理

### 1. 风险自适应速度

原 R2-Gap-Lite 已经根据可停止距离和曲率计算安全速度：

```text
v_safe = min(v_brake, v_curve, v_max)
```

本次新增综合风险项：

```text
risk =
  w_free    * free_distance_risk
+ w_clear   * low_clearance_risk
+ w_unknown * unknown_ratio
+ w_dyn     * dynamic_obstacle_risk
```

最终速度变为：

```text
v_cmd = v_safe * (1 - risk_speed_gain * risk)
```

含义是：即使当前轨迹还没有碰撞，只要前方距离变短、净空变小、未知 beam 增多或检测到动态逼近，车辆也会提前降速。

### 2. 候选轨迹置信度

每条候选弧线现在额外计算 `confidence`：

```text
confidence =
  clearance_confidence
* known_beam_confidence
* stability_confidence
* dynamic_confidence
* risk_confidence
```

它不是简单判断轨迹是否可行，而是评估这条轨迹“有多可靠”：

- 净空越大，置信度越高。
- 未知 beam 越少，置信度越高。
- 转角相对上一帧变化越小，置信度越高。
- 动态障碍风险越低，置信度越高。
- 综合风险越低，置信度越高。

最终评分由原来的风险评分扩展为：

```text
score = base_score * (0.5 + 0.5 * confidence)
      + confidence_weight * confidence
      - risk_weight * risk
```

这样候选轨迹不仅要“远”和“快”，还要稳定、可信、低风险。

### 3. 对手车动态障碍预测

节点现在保存上一帧 `LaserScan`，并传入 `delta_time`。核心根据同一 beam 的距离变化估计相对逼近速度：

```text
closing_speed = (range_previous - range_current) / delta_time
```

当 `closing_speed` 超过阈值时，认为该方向存在动态障碍逼近风险：

```text
dynamic_obstacle_risk =
clip((closing_speed - threshold) / saturation, 0, 1)
```

同时加入距离权重，近处逼近的风险更高。若两帧时间间隔过大，则不使用动态预测，避免旧数据误导控制。

- `roboracer_china_2025/reachability_core.py`

  - `select_reachable_gap()` 新增 `previous_ranges` 和 `delta_time` 输入。
  - 新增动态风险剖面、候选风险、候选置信度和风险调速逻辑。
