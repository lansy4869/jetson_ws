# 第二次修改：AC-ARPS 自适应保形 Ackermann 残差预测安全层

日期：2026-07-06

## 修改目标

在不改动 battle_fast2 原有间隙选择、状态机和经验速度策略的前提下，
在**最终发布 `/drive` 之前**增加一层残差式预测安全过滤器（AC-ARPS）：

1. 原始算法判断安全时，速度和转角完全透传（一位小数都不改）；
2. 不安全时优先只减速（保持 δ_base），减速仍不安全才叠加 |Δδ|≤0.105 rad（约 6°）的转角残差；
3. 使用 Ackermann 自行车模型 + 三圆车体包络预测未来 0.40~0.85 s 轨迹
   （时域随速度自适应：H(v)=clip(τ_delay+v/a_brake, 0.40, 0.85)），并建模控制延迟与制动斜率；
4. 连续两帧径向 closing speed 的保守型方向性 TTC（取扇区第 20 百分位抗单点噪声）；
5. 「预测净空高于实际净空」危险侧残差的在线保形余量 q_t（Adaptive Conformal 思路），
   自动放大/收缩安全膨胀半径，默认关闭（阶段 3 再开）。

## 修改/新增文件

- `roboracer_china_2025/ac_arps_core.py`【新增】安全层核心，无 ROS 依赖，纯 numpy，可离线单测
- `roboracer_china_2025/ac_arps_ros.py`【新增】ROS 胶水：shield_* 参数声明/实例构建/调试消息，两份节点共用
- `roboracer_china_2025/battle_fast2_node.py`【修改】三处集成点；reachability 与原启发式两条发布路径都过安全层
- `battle_fast2_node.py`（包根目录独立副本)【修改】同样的三处集成点
- `launch/battle_fast2.launch.py`【修改】暴露 shield_* 常用参数
- `test/test_ac_arps_core.py`【新增】18 项单元测试

## 三处集成点（两份节点文件一致）

```text
位置一  回调开头、nan_to_num 之前:
        raw_ranges = np.asarray(data.ranges, dtype=np.float32).copy()
        （inf=量程内无回波/自由空间，NaN=无效测量；安全层不吃补零后的虚构距离）

位置二  __init__ 中:
        self.predictive_shield = build_shield_from_parameters(self)

位置三  Follow/chaoche 作用到基础速度之后、drive_pub.publish 之前:
        drive_msg = self.apply_predictive_shield(data, raw_ranges, drive_msg)
```

原 600 多行控制流程、P/D/speed_rate/turn_rate、超车与跟随状态机全部未动。
安全层内部异常时自动透传基础指令并打 error 日志，绝不因自身故障接管车辆。

## 分级介入逻辑

```text
第 0 级  预测净空 c_min>0 且 v_base≤TTC 限速 → 原命令逐位透传
第 1 级  速度候选 [0.85, 0.70, 0.50, 0.25, 0] × v_base，δ 不变，取第一个安全者
第 2 级  转角残差 ±0.035/±0.070/±0.105 rad（|Δδ| 从小到大），每档速度从高到低
第 3 级  无安全候选 → v=0 紧急制动，δ 取 v=0 候选中预测净空最大者
```

speed_only=True 时第 2 级整体禁用，紧急制动保持 δ_base。

# 第一次修改：R2-Gap-Lite 可达性核心

日期：2026-06-29

## 修改目标

在保留原 `battle_fast2_node.py` 可运行启发式逻辑的基础上，新增一套无地图、无全局定位的可达性风险感知控制核心。新核心优先运行；如果无解或异常，默认回退到原来的最大间隙启发式流程。

## 修改文件

- `roboracer_china_2025/reachability_core.py`
- `roboracer_china_2025/battle_fast2_node.py`
- `launch/battle_fast2.launch.py`
- `test/test_reachability_core.py`

## 核心新增功能

### 1. 新增 R2-Gap-Lite 可达性核心

新增 `reachability_core.py`，不依赖 ROS 2，只依赖 Python 标准库和 `numpy`。

核心流程：

```text
LaserScan ranges
-> 有效 beam / 未知 beam 建模
-> 枚举 Ackermann constant-curvature 候选弧线
-> 结合前向 beam 净空和车辆矩形扫掠体评估风险
-> 按制动距离、系统延迟、曲率限制计算安全速度
-> 用连续评分选择 steer + speed
```

这替代了“只选最大空隙中心角”的单一决策方式。

### 2. `battle_fast2_node.py` 接入新核心

节点启动后默认启用可达性核心：

```python
use_reachability_core = True
reachability_fallback_to_original = True
```

每次收到 `/scan` 后，节点会先尝试：

```text
raw LaserScan -> select_reachable_gap() -> AckermannDriveStamped
```

如果结果有效，直接发布 `/drive` 并返回；如果结果无效或核心抛异常，则默认继续执行原来的启发式算法。

### 3. 保留原算法作为安全回退

原 `middle_line_callback()` 的旧逻辑没有删除。新增逻辑只在回调开头插入：

```text
try_reachability_control()
成功：发布新控制并 return
失败：进入原始启发式流程
```

这样实车调试时可以快速切回旧逻辑。

### 4. 新增可调参数

节点新增参数：

- `use_reachability_core`
- `reachability_fallback_to_original`
- `reachability_max_speed`
- `reachability_min_speed`
- `reachability_wheelbase`
- `reachability_vehicle_width`
- `reachability_horizon`
- `reachability_max_steer`
- `reachability_steer_samples`
- `reachability_base_margin`
- `reachability_system_delay`
- `reachability_max_brake_accel`
- `reachability_max_lateral_accel`
- `reachability_unknown_weight`
- `reachability_range_max`

`battle_fast2.launch.py` 额外暴露了常用参数：

```bash

```

示例：


## 行为变化

### 原逻辑

```text
障碍分段 -> 最大空隙区间 -> max_dir_index -> PD 转角 -> 启发式 speed_rate
```

### 新逻辑

```text
候选转角弧线 -> 车辆扫掠风险 -> 延迟制动限速 -> 曲率限速 -> 连续评分
```

主要区别：

- 不再只根据角度空隙大小选择方向。
- 会考虑车辆宽度和安全裕量。
- 会根据前方可停止距离自动压速度。
- 会惩罚无效、未知或丢失的 LiDAR beam。
- 会惩罚转角突变，减少左右摇摆。
