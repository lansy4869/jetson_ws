## 技术方案概述

将当前 `mpcbattle` 实验链路升级为“局部可达性监督的 MPC Safety Shield”。Battle Fast2 继续输出 reactive 命令，同时发布局部可达性诊断；Drive Arbiter 订阅诊断后对 MPC 名义命令执行五档安全屏蔽：GREEN 直通、YELLOW 限速、ORANGE 转角融合、RED reactive 接管、BLACK 停车。

## 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 语言 | Python + ROS2 | 现有 `battle_fast2_node` 和 `drive_arbiter` 均为 Python ROS2 节点，改动小。 |
| 消息 | `std_msgs/Float32` + `AckermannDriveStamped` | 避免新增自定义消息，便于快速上车和测试。 |
| 安全逻辑 | 纯函数核心 + ROS2 封装 | `drive_arbiter_core.py` 可脱离 ROS 做单元测试。 |

## 架构设计

```text
mpc_control -> /mpc/drive_nominal
battle_fast2_node -> /battle_fast2/drive_reactive
battle_fast2_node -> /battle_fast2/front_clearance_m
battle_fast2_node -> /battle_fast2/risk_min_margin_m
battle_fast2_node -> /battle_fast2/reactive_speed_limit_mps
drive_arbiter -> Safety Shield -> /drive
```

## 模块划分

| 模块 | 职责 | 依赖 |
|------|------|------|
| `battle_fast2_node.py` | 发布 reactive 命令和 Shield 诊断 | `reachability_core.py` |
| `drive_arbiter_core.py` | 执行 GREEN/YELLOW/ORANGE/RED/BLACK 纯函数决策 | 无 ROS 依赖 |
| `drive_arbiter_node.py` | 订阅 ROS topic，发布最终 `/drive` | `drive_arbiter_core.py` |
| `global_mpc_battle_arbiter.launch.py` | 连接 MPC、Battle Fast2 和 Shield 参数 | ROS2 launch |
| `paper/` | 将论文主线改为局部可达性监督 Safety Shield | 当前代码实现 |

## 接口设计

### Battle Fast2 诊断输出

- `/battle_fast2/front_clearance_m` (`std_msgs/Float32`): 第一版取 `ReachabilityResult.free_distance`。
- `/battle_fast2/risk_min_margin_m` (`std_msgs/Float32`): 第一版取 `ReachabilityResult.min_clearance`。
- `/battle_fast2/reactive_speed_limit_mps` (`std_msgs/Float32`): 第一版取 `ReachabilityResult.speed`。

### Drive Arbiter Shield 输入

- `mpc_drive_topic`: 默认 `/mpc/drive_nominal`。
- `reactive_drive_topic`: 默认 `/battle_fast2/drive_reactive`。
- `front_clearance_topic`: 默认 `/battle_fast2/front_clearance_m`。
- `risk_min_margin_topic`: 默认 `/battle_fast2/risk_min_margin_m`。
- `reactive_speed_limit_topic`: 默认 `/battle_fast2/reactive_speed_limit_mps`。

## 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 是否新增自定义消息 | 否 | 减少构建和部署复杂度。 |
| Shield 诊断缺失时怎么办 | 降级到原仲裁逻辑 | 不让新增诊断 topic 破坏旧链路。 |
| 局部风险高但 reactive 无效时怎么办 | 停车 | 实车安全优先。 |
| ORANGE 是否直接切 reactive | 不直接切，先融合 | 体现 Safety Shield 的连续干预，而不只是 fallback。 |
